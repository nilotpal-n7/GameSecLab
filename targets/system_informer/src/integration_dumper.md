# Wiring the Pro gate into System Informer — the memory dumper, end to end

This is the first feature wired all the way through, so the pattern is proven once before the Memory
Editor / DLL Injection / cross-DLL handshake follow the same shape. All edits are in the user's fork; the
licensing core (`src/*.cpp`, `src/*.h`) is built into `sip_progate.lib` and linked into `SystemInformer`.

## 1. Build the licensing core as its OWN DLL (not a static lib) — the real CRT trap

The prebuilt `demo/licenseseat/lib/licenseseat.lib` is **`/MD` (dynamic CRT), `_MSC_VER=1900`**; System
Informer is **`/MT` (static CRT)**. A static `sip_progate.lib` linked into `SystemInformer.exe` would hit
`LNK2038 "RuntimeLibrary mismatch: MT vs MD"` (the SDK lib embeds `/FAILIFMISMATCH:"RuntimeLibrary=..."`)
— two CRTs cannot coexist in one image. There is no source for the SDK, so we cannot rebuild it `/MT`.

So the licensing core is its **own DLL**, `sip_progate.dll`, built `/MD` with the toolset that matches the
SDK, linking `licenseseat.lib` + `bcrypt.lib` + `VMProtectSDK64.lib` + **OpenSSL `libcrypto64MD.lib`**
(licenseseat.lib's `EVP_*` live in libcrypto — `C:\Program Files\OpenSSL-Win64\lib\VC\`) + `advapi32.lib`
(its device-fingerprint `Reg*` calls) + `crypt32`/`ws2_32`/`user32`. At runtime `sip_progate.dll` therefore
also needs `libcrypto-3-x64.dll` beside it (ship it with the installer). `SystemInformer.exe` (`/MT`) calls it
only across the **primitives-only C ABI in `pro_gate.h`** — no C++ object, no CRT allocation, ever crosses
the boundary, so each module keeps its own CRT. This is why `pro_gate.h` was designed POD-only. Ship the
matching VC++ runtime (or the SDK's `/MD` deps) beside the DLL.

Build flags for the DLL: `/MD /Zi /DEBUG /MAP` so the VMProtect pass resolves `sip_gate_init` /
`sip_access_mask` / `sip_xdll_respond`; then run the `.vmp` pass on `sip_progate.dll` itself. Both
`sip_progate.dll` and `plugins\ExtendedTools.dll` are protected; `SystemInformer.exe` need not be.

`SystemInformer.exe` reaches the DLL via a thin import lib (`sip_progate.lib` generated by the DLL build —
an *import* stub, not the static CRT-bearing lib) or `LoadLibrary`/`GetProcAddress`. Either way the call
site is just `pro_gate.h`.

### 1a. Wire the DLL into the SystemInformer project

`mdump.c` now `#include "pro_gate.h"` and calls `sip_gate_init` / `sip_access_mask`. For the SI build
(`SystemInformer.vcxproj`) to find the header and the import stub, add (Release|x64 and Debug|x64):

- **C/C++ > General > AdditionalIncludeDirectories** += `$(SolutionDir)..\..\targets\system_informer\src`
  (or wherever this repo's `src/` is — it holds `pro_gate.h`). Keeps one source of truth; no copies.
- **Linker > Input > AdditionalDependencies** += `sip_progate.lib` (the DLL's *import* lib — tiny, CRT
  neutral; NOT a static CRT lib, so no `/MT` vs `/MD` clash).
- **Linker > General > AdditionalLibraryDirectories** += the folder holding `sip_progate.lib`
  (default `demo\systeminformer\sip\bin`).
- **Deploy**: `sip_progate.dll` must sit next to `SystemInformer.exe` at runtime (plus the VC++ `/MD`
  runtime, or the LicenseSeat `/MD` deps). The Inno Setup script installs it beside the exe.

Build the DLL first with `src\build_sip_progate.cmd` (it emits `sip_progate.dll` + `sip_progate.lib` +
`sip_progate.map` into `demo\systeminformer\sip\bin`).

## 2. Initialise once at startup

In `SystemInformer`'s early init (e.g. `main()` / `PhInitialization` path), after phlib is up:

```c
#include "pro_gate.h"
...
SipInitResult pro = sip_gate_init(NULL);   /* NULL = default machine-file search path */
/* Do NOT branch features on this result. UI may grey-out Pro menus with sip_is_pro(),
   but the privileged operations are guarded by the ACCESS_MASK below, not by this flag. */
```

## 3. Gate the dumper by the ACCESS_MASK it opens the process with

System Informer's Process Memory Dumper opens the target process, then calls `PhWriteMiniDumpProcess`.
In THIS fork the dumper lives in **`SystemInformer/mdump.c`** (not `misccmd.c`, which does not exist here);
`procprp.c` / `phsvc/svcapi.c` also open process handles for the forensic paths. Find where `mdump.c`
obtains its process handle and replace the fixed desired-access with the entangled mask:

```c
/* BEFORE (illustrative): a fixed mask, trivially patchable, and the gate would be a separate `if`. */
/* status = PhOpenProcess(&processHandle, PROCESS_DUP_HANDLE | PROCESS_QUERY_INFORMATION |
                          PROCESS_VM_READ, processId); */

/* AFTER: the access itself carries the license decision. 0x0450 = PROCESS_QUERY_INFORMATION |
   PROCESS_VM_READ (what a minidump needs); unlicensed callers get 0x1000 (SUSPEND_RESUME) instead. */
ACCESS_MASK want = sip_access_mask(SIP_FEAT_DUMP);
status = PhOpenProcess(&processHandle, want, processId);
if (!NT_SUCCESS(status)) {
    /* Unlicensed: the kernel denied the forensic rights. Surface SI's normal access-denied path. */
    PhShowStatus(hwndDlg, L"Unable to dump the process", status, 0);
    return;
}
/* Licensed: processHandle has PROCESS_VM_READ, PhWriteMiniDumpProcess succeeds as usual. */
```

The point: there is no boolean to flip. An unlicensed build opens the handle with `0x1000`, so
`PhWriteMiniDumpProcess` fails inside `MiniDumpWriteDump` with `STATUS_ACCESS_DENIED` — far from any
recognizable check site. A patched `.text` makes `sip_gate_init` fail to decrypt, so `g_state.mask_base`
stays zero and the mask is the trap regardless.

## 4. Verify the contrast

- **Unprotected Community build, no license** → dump fails with access denied.
- **With a valid `.sipm` for this machine + this build** → dump works.
- **Patch one `.text` byte** → `sip_gate_init` returns `SIP_KDF_MISMATCH`; dump fails. (`DEMO_SOFT` logs
  the code instead of corrupting, so it is filmable.)

## 5. The other features (same pattern)

- **Memory Editor write** (`SystemInformer/memedit.c`): open with `sip_access_mask(SIP_FEAT_EDIT)`
  (0x0038 = `PROCESS_VM_WRITE | PROCESS_VM_OPERATION`); without it the writer handle lacks VM_WRITE.
- **DLL Injection**: this fork has no `misccmd.c` injector; locate the inject command path (grep
  `CreateRemoteThread` / `LdrLoadDll` thunk; the plugin `AgentTools` is a candidate) and open with
  `sip_access_mask(SIP_FEAT_INJECT)` (0x002A = `PROCESS_VM_WRITE | PROCESS_VM_OPERATION |
  PROCESS_CREATE_THREAD`). TODO(build): confirm the exact call site.
- **Cross-DLL handshake**: `ExtendedTools.dll` sends a 32-byte challenge; `SystemInformer.exe` answers
  with `sip_xdll_respond`; the plugin recomputes and compares. Only a genuinely Pro-verified pair match.

> KPH / ksi kernel driver must be **OFF** for the demo build. With KPH loaded, `KphOpenProcess` can grant
> access the user-mode ACCESS_MASK gate would deny, bypassing the whole scheme. Ship the demo with KPH
> disabled and say so on camera.
